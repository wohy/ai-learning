# 识别企业中 LLM 和 RAG 潜在的应用场景的方法论
## 1. 分析业务流程，找出业务中依赖大量知识或信息处理的环节
### 复杂决策
在需要多维度信息综合分析与判断的业务流程中，RAG 可以为决策者提供实时的信息支持。
可用于 压缩和整理非格式化信息
### 重复性内容生成
企业中大量重复且标准化的内容生成任务
这类问题往往可以用程序去归纳流程，在这个流程之下，用 LLM 和 RAG 去填充每个环节，最终得到想要的内容。
### 用户交互场景
思考哪些交互场景可以使用 自然语言 简化、替代
## 2.识别问题，找出当前流程中的痛点，并识别 LLM 和 RAG 在解决这些痛点中的作用
### 信息碎片化和难以系统化输出
各个部门之间都有自己的文档和知识库，甚至有的只存在于员工的大脑里，非常分散，每次需要的时候，都要去拉人沟通，难以形成一个体系化的输出。
使用 LLM 和 RAG 能够通过自动化整合固定信息源的内容，定期获取信息，统一整理（有可能重新生成）到公司的知识库中，将分散的知识转化为结构化输出，提高效率。
### 人工处理效率低下
在需要人工参与的繁琐任务中，重复操作和低效沟通是常见问题。通过 LLM 自动化这些任务，可以**让团队成员专注于更有创造力的工作**。**创造力**无可替代
## 3. 小步快跑，快速迭代，找到需求之后，快速做出应用，验证效果，验证成功再迭代
### 构建最小可行产品（MVP）
试点、哪怕从脚本开始
### 数据驱动的迭代优化
持续收集用户反馈、做 A/B test 实验，持续收集问题反馈，进行调优，最终评估选择默认模型，并持续迭代
