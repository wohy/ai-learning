# 构建聊天机器人
## 把知识资料输入给大模型的方式
- 两种方式：
    - Fine-tuning
        知识整合：直接把知识数据融入到模型参数中
        知识更新：每次更新都需要重新训练大模型
        响应速度：速度很快，直接给出答案
        实时性：很难保证实时性
        人为干预：只能通过 prompt 进行干预
        个性化定制：针对特定领域进行深度定制
    - RAG
        知识整合：存储在外部知识库
        知识更新：更新成本非常低，只需要在知识库插入记录
        响应速度：需要先检索，在组织答案
        实时性：知识库可以保持实时更新
        人为干预：可以通过知识库的语料和 prompt 去干预
        个性化定制：依赖于通用大模型

- Fine-tuning 更适用的场景
    特定场景下的高一致性和定制化：比如让助手回答品牌宣传和企业文化相关内容。
    数据量充足并且稳定：拥有高质量的对话原始数据的情况下，如果基于现有数据做对话助手，可以直接使用原始数据微调。
    强个性化需求：比如文言文理解和输出，需要使用大量文言文语料微调之后，才能适当地满足要求。
    高速响应：相比 RAG，微调模型能够直接输出有效内容，所以响应速度理论上要比先检索再生成快很多。

## 大致流程
把文档或者文章等的上下文和用户的问题提交给大模型，大模型给出相应的回答

## 构建知识库
### token 的概念
大模型对输入、输出的长度有限制，它的计量单位为 token
一个 token 对应了一个英文单词、一个英文短语或者一个汉字
比如 OpenAI 的 GPT-3.5 模型，最大 token 长度是 4k，这个数量包含了输入和输出的总和
### 知识切片
一些文章或者文档内容过大，需要对其进行切片

## 如何切割文档
1. \n 换行符切割
现代 RAG 理论中称为 “内容感知切割”
2. 固定长度切割
可以使用一定长度的 buffer 进行优化，段前或者段后的 buffer，至刚好遇见句号
3. 基于 token 的切割
4. 递归切割
5. 基于语义理解的切割

## 知识库构建完成，开始应用实现
1. 实现大模型服务 
大模型调用接口 api
需要接入统一风控，确保回答内容的合法合规

2. 对话应用服务
针对不同的业务构建不同的 prompt 模版，这里的 prompt 会使用占位符和参数控制哪里需要什么类型的上下文，传递给大模型服务系统之后，才会拼出完整的 prompt。
还会提供一个 message cache 功能，每个用户都有一个 cache ，存储用户最新的三条提问消息，使用 FIFO 的方式存储，每次提问都会将这部分 cache 也都提交给大模型

3. 使用 SSE 或者 webSocket 支持流式对话

### SSE
SSE（Server-Sent Events）是一种允许服务器主动向客户端发送实时更新数据的技术。通常用于建立从服务器到客户端的单向数据流（就非常适合流式对话场景）。在 SSE 中，客户端通过一个 HTTP 请求与服务器建立连接，服务器可以在连接期间不断地推送事件到客户端，直到收到截止符，而无需客户端重复发送请求。
