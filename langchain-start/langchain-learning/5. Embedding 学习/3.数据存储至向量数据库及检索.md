# Retriever 检索
检索出几条 距离最近的索引，并可通过索引得到需要的答案内容和距离


## 检索优化
### MultiQueryRetriever
使用 LLM 去将用户的输入改写成多个不同写法，从不同的角度来表达同一个意思，来克服因为关键词或者细微措词导致检索效果差的问题。
在 RAG 中 retriever 的前期就引入 llm 对语意的理解能力，来解决纯粹的相似度搜索并不理解语意导致的问题。

### Document Compressor
Retriever 的另一个问题，参数 K （检索返回的文档数）的设置，较小时，因为自然语言的特殊性，可能相似度最高的不一定是答案，如果设置过大，就会导致返回大量的文档内容，导致超出 LLM 上下文窗口。

观察返回的 Document 内容可以发现，其中有一部分是没有参考价值的内容，无关用户所提问题，不仅会干扰 LLLM 的生成质量，还会浪费一部分 Token，并可能超出 LLM 的上下文长度限制，所以我们可以再一次提取其中核心的内容，进一步对 Document 进行压缩

`ContextualCompressionRetriever`也就是会自动对上下文进行压缩的 Retriever


## ​Retriever的核心作用​​
### 1. ​​语义匹配而非关键词匹配​​
- Retriever 利用​​嵌入模型​​（Embedding Model）将用户查询和文档转换为高维向量（如768维或1024维），通过计算向量间的​​余弦相似度​​或​​欧氏距离​​，实现基于语义的相似性搜索。
- 与传统关键词检索（如Elasticsearch）不同，它能理解同义词、上下文关联和抽象概念（例如“环保”与“可持续发展”的语义关联）。
### ​2. ​在RAG框架中的关键地位​​
- 在检索增强生成（RAG）系统中，Retriever 负责从向量数据库中召回与用户问题相关的文档片段（Context），再交给大语言模型（LLM）生成最终回答。
- 例如：用户问“气候变化的影响”，Retriever 会召回与“温室效应”“海平面上升”等语义相关的文档块。
### 3. ​​支持多种检索策略​​
- **​相似度搜索​​（Similarity Search）**：返回与查询向量最相似的Top K个结果。
- **​最大边际相关性​​（MMR）**：平衡相关性与多样性，避免结果重复（例如在推荐系统中）。
- ​**​阈值过滤​​（Score Threshold）**：仅返回相似度分数超过设定值的结果（如 score_threshold=0.8）。
